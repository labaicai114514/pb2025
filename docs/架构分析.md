# pb2025_sentry_nav 导航框架架构分析

> 面向后续研究/拓展/实车迁移的代码导读。所有路径相对 `src/pb2025_sentry_nav/`。

## 1. 系统总览

分层结构（自底向上）：

```
感知层      mid360 点云+IMU (gz 或 livox 驱动)  → ign_sim_pointcloud_tool(仿真补 time)
里程计层    point_lio (lidar_odom) → loam_interface → odom
定位层      small_gicp_relocalization (先验点云重定位, map->odom)
感知加工    terrain_analysis(_ext) (4m 内/外地形), sensor_scan_generation
导航层      NAV2 (planner/controller/behavior/costmap) 
执行层      pb_omni_pid_pursuit_controller → cmd_vel → 底盘
辅助        fake_vel_transform (云台自旋虚拟系), pb_teleop_twist_joy
```

## 2. 坐标变换设计（本项目核心创新）

关键点：**雷达原点 `lidar_odom` 与底盘原点 `odom` 是隐式耦合的**（mid360 斜置导致二者姿态不一致）。

```
map ──static(建图时) / small_gicp(导航时)──> odom
odom ──sensor_scan_generation──> chassis
chassis ──robot_state_publisher──> base_footprint, gimbal_yaw, gimbal_pitch, front_mid360 ...
gimbal_yaw ──fake_vel_transform──> gimbal_yaw_fake   ← NAV2 的 robot_base_frame
```

- `loam_interface` (`src/loam_interface/`): 读 point_lio 输出的 `/cloud_registered`(在 lidar_odom 系)，发布 `lidar_odom → odom` 变换（含外参 0.16,0,0.256 / rpy 0,30°,90°，mid360 斜置 30° 侧装）
- `sensor_scan_generation`: 把 odom 系点云转回雷达系 `front_mid360`，并发布 `odom → chassis`
- **为什么 NAV2 的 base frame 是 `gimbal_yaw_fake`**: 云台自旋时底盘坐标系会跟着转，让 NAV2 以为本体朝向恒定，从而在云台旋转时也能正常建图/规划（详见 fake_vel_transform 子仓库 README）

## 3. 节点/主题图（导航模式）

```
gz(仿真)               导航栈(namespace=red_standard_robot1)
├ livox/lidar 点云 ───→ ign_sim_pointcloud_tool ─→ point_lio ─→ loam_interface ─→ sensor_scan_generation ─→ terrain_analysis(_ext)
├ livox/imu ─────────→ point_lio                                           │
├ odometry ──────────→ fake_vel_transform (odom+云台角 → gimbal_yaw_fake)   └→ odom→chassis TF
└ joint_states ──────→ fake_vel_transform
                                                     small_gicp_relocalization (先验 PCD → map→odom)
                                                                  NAV2 组件容器 (nav2_container):
                                                                  controller_server(OmniPidPursuit)
                                                                  planner_server(ThetaStar)
                                                                  behavior_server(含 BackUpFreeSpace)
                                                                  bt_navigator / smoother / costmaps
                                                                  (local/global costmap 用 IntensityVoxelLayer)
```

## 4. 自定义插件（扩展点 ①）

| 插件 | 代码 | 作用 |
|---|---|---|
| `pb_nav2_costmap_2d::IntensityVoxelLayer` | `pb_nav2_plugins/src/layers/intensity_voxel_layer.cpp` | 读 terrain_analysis 输出的点云 intensity（=障碍物离地高度），生成 3D 代价体素层，融合进 NAV2 costmap |
| `pb_nav2_behaviors/BackUpFreeSpace` | `pb_nav2_plugins/src/behaviors/back_up_free_space.cpp` | 倒车行为：向无障碍空间后退（配合哨兵撤退战术） |
| `pb_omni_pid_pursuit_controller::OmniPidPursuitController` | `pb_omni_pid_pursuit_controller/` | 全向底盘 PID 路径跟踪（x/y/yaw 三通道 PID，适配麦轮/全向轮文法） |

注册方式：`pluginlib_export_plugin_description_file(nav2_core behavior_plugin.xml)` + config 中 `plugin:` 字段。
**新增自定义导航行为/层的套路 = 参考这两个包的结构。**

## 5. 参数体系（扩展点 ②）

`pb2025_nav_bringup/config/simulation/nav2_params.yaml`（608 行）按节点分节：
- `point_lio`, `loam_interface`, `sensor_scan_generation`, `terrain_analysis(_ext)`, `fake_vel_transform`, `small_gicp_relocalization`
- `slam_toolbox`（建图模式）
- `bt_navigator`（干路导航树, robot_base_frame 等）
- `controller_server`（PID 参数等）
- `local/global_costmap`（层配置、订阅地形主题）

注意：仿真/实车参数文件分离：`config/simulation/` vs `config/reality/`。

## 6. 启动装配（扩展点 ③）

- `pb2025_nav_bringup/launch/rm_navigation_simulation_launch.py` — 仿真主入口
  - `slam` 参数 → 切换 `slam_launch.py`(slam_toolbox) 或 `localization_launch.py`(map_server+small_gicp)
  - `use_composition` → NAV2 全栈进单个 `component_container_isolated`
  - namespace 默认 `red_standard_robot1` → 支持多机器人（`rm_multi_navigation_simulation_launch.py`）
  - 所有 launch 参数表见上游 README 2.4 节

## 7. NAV2 集成细节（研读重点）

1. 全栈生命周期管理：`lifecycle_manager_navigation` 统一 configure→activate，失败会 bond 断连检测
2. 行为树：`pb2025_nav_bringup/behavior_trees/` 下有自定义 BT XML（可扩展哨兵战术动作）
3. 速度平滑：`velocity_smoother` 在 controller 输出后限速，`cmd_vel` 最终给底盘
4. 手柄（PS4）控制与 NAV2 并存：`pb_teleop_twist_joy` 映射见 nav2_params.yaml

## 9. 常见排查

| 现象 | 原因/处理 |
|---|---|
| EGL 报错、传感器无数据 | 装 NVIDIA 用户态 GL（见 README_部署说明 3.1） |
| `Failed init_port fastrtps_port...` | 孤儿进程/SHM 残留，杀进程+删 /dev/shm/fastrtps* |
| 容器加载卡住 | 同上；或 `use_composition:=False` |
| `simple_competition_1v1.py Exec format error` | 已修（shebang） |
| local_costmap 一直等 transform | 传感器无数据 → 先修渲染 |
